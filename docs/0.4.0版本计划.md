# campus-trading v0.4.0 版本计划

> 目标：运营化——完善交易闭环（订单超时关闭）、补齐运营后台与信用体系，让平台从"能演示"走向"能上线运营"。

## 一、GitHub OAuth 第三方登录 ✅

> 练"外部系统对接 + 回调 + 校验"的落地功能，作为平台第二种登录方式（除学号密码外）。

### 1.1 流程（OAuth2 Authorization Code）

```
前端点"GitHub 登录" → 跳 GitHub 授权页（带 client_id/redirect_uri/state）
→ GitHub 授权 → 302 回调后端（带 code + state）
→ 后端校验 state（Redis 一次性）→ code 换 access_token（带 client_secret）
→ 带 token 调 GitHub API 拿用户信息 → 查库/自动建号 → 签发自有 JWT
→ 302 跳回前端（hash 路由带 token/id/username）→ 前端存登录态 → 登录完成
```

### 1.2 后端实现（已完成 ✅）

| 文件 | 说明 |
|------|------|
| `OAuthProperties` | GitHub 配置绑定（client_id/secret/redirect/三个URL） |
| `OAuthService` + `OAuthServiceImpl` | 核心：state校验 → 换token → 取用户 → 建号 → 签JWT |
| `OAuthController` | `/api/oauth/github/login`（返回授权URL）+ `/callback`（处理回调+302跳前端） |
| `WebMvcConfiguration` | 白名单加 `/api/oauth/**`（匿名接口） |
| `UserMapper` | `getByGithubId`、`insertOauthUser`（`@Options` 回填主键） |
| `user` 表 | 新增 `oauth_github_id` 列 |

### 1.3 前端实现（已完成 ✅）

| 文件 | 说明 |
|------|------|
| `LoginModal.vue` | "使用 GitHub 登录"按钮 + handler |
| `OAuthCallbackView.vue` | 接收 token/id/studentId/username，拼完整登录态 |
| `router/index.js` | `/oauth/callback` 路由（hash 模式） |
| `api/user.js` | `getGithubLoginUrl` |

### 1.4 关键知识点

- **state 防 CSRF**：后端生成存 Redis，回调时删除即校验（一次性消费）
- **code 换 token 带 client_secret**：必须放后端，secret 不进浏览器
- **Bearer token**：访问 GitHub 受保护资源的凭证
- **外部用户映射**：合成学号 `github_{id}` + 随机密码（`password NOT NULL` 的兜底）
- **复用自有 JWT**：OAuth 登录后签发和密码登录一样的 JWT，后续拦截器零改动

## 二、订单超时自动关闭

### 2.1 现状与问题

- 下单后商品被 CAS 锁为已售，但没有超时机制——用户占着不付，商品就永远卖不了
- 现有 RabbitMQ 只做通知，未用延迟队列

### 2.2 方案：RabbitMQ 延迟消息

用 **TTL + 死信队列（DLX）** 实现延迟：

```
下单成功
  → 发延迟消息到 "order.delay" 队列（TTL=30min）
  → 到期进入死信队列 "order.dead"
  → Consumer 消费：查订单仍处于初始状态 → 关闭订单 + CAS 回滚商品 status=1
```

**计划**：
- [ ] `RabbitMqConfig` 新增延迟队列 + 死信队列配置（TTL、DLX、路由）
- [ ] `OrderServiceImpl.create` 发延迟消息；新增 `close`（关闭订单 + 回滚商品）
- [ ] `OrderTimeoutConsumer`（新增）：查单、判状态、关单、回滚商品
- [ ] 幂等保护：消费者判订单状态 + Redis 去重，避免重复关单/重复回滚

### 2.3 涉及文件

| 层 | 文件 |
|----|------|
| 配置 | `config/RabbitMqConfig`（延迟队列+死信） |
| 消费 | `mq/OrderTimeoutConsumer`（新增） |
| 服务 | `OrderServiceImpl`（create 发延迟消息、新增 close 方法） |

## 三、运营管理后台

### 3.1 现状

- 平台只有普通用户角色，无管理员
- 举报、商品下架、用户禁用都只能直接改数据库

### 3.2 方案

**新增管理员角色 + 运营后台页面**：

- `user` 表加 `role` 字段（0 普通 / 1 管理员）
- 管理端接口统一 `/api/admin/**`，JWT 校验角色（新增管理员拦截器或注解）
- 功能：
  - [ ] 商品管理：列表、下架/上架、删除违规商品
  - [ ] 举报处理：查看举报、标记已处理、联动下架/封禁
  - [ ] 用户管理：列表、禁用/启用
  - [ ] 数据看板：商品/订单/用户统计（复用现有 `StatsController`）

### 3.3 前端

- 新页面 `AdminView.vue`（或独立 admin 路由分组）
- 前端路由守卫按角色控制
